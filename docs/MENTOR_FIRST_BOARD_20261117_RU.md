## Что прислать до первого включения

1. Фото обеих сторон платы, полное название, ревизия, маркировка модуля,
   flash size, схема/ссылка на изготовителя, USB-разъём и USB-UART.
2. Источник питания: модель, выходное напряжение, ограничение тока,
   способ питания платы. Схема USB/внешнего питания и исключение обратной подпитки.
3. Измерительные приборы и подключение их земли. Нужен контроль реального уровня
   GPIO, не только UART-лог или значение в интерфейсе.
4. Кандидат GPIO и его назначение по схеме: профиль WROOM использует GPIO26,
   C6 GPIO2. Это не подтверждение пригодности этих выводов на конкретной плате.
   Проверить конфликты с flash, USB/UART, загрузкой и встроенной периферией.
5. Для будущего отдельного этапа с реле: модель, datasheet, схема драйвера,
   напряжение катушки/питания, совместимость входа с 3.3 V, active-high/low,
   входные подтяжки, наличие и схема оптоизоляции, COM/NO/NC, защитные элементы.
   Название «оптоизолированное» само по себе изоляцию не подтверждает.
6. Точные SHA, версия IDF, параметры сборки и хеши ELF/BIN. Секреты, Wi-Fi пароль,
   приватные сертификаты и дампы с учётными данными в GitHub не отправлять.

## Этап A: только плата, без реле и нагрузки

Проводит наставник после отдельного разрешения владельца и проверки схемы.

1. Реле, драйвер и любые нагрузки физически отсоединить. Работать только с
   низковольтным питанием по документации конкретной платы. Не подавать 5 V
   на 3V3/GPIO, не соединять два источника параллельно. USB не должен подпитывать
   отключённую плату. Токовый лимит выбирается по документации платы.
2. При снятом питании проверить проводку, короткое замыкание и внешний OFF-bias
   по выбранной полярности. Подключать только подходящие измерительные щупы.
3. После разрешённой прошивки снять cold-start, reset и software reboot:
   ожидается inactive GPIO до/после инициализации, без активного импульса.
   Любой неожиданный фронт, нагрев, запах, провал питания или reset-loop:
   остановить опыт, снять питание и сохранить наблюдения.
4. Зафиксировать плату, GPIO/полярность, питание, SHA образа, осциллограммы и логи.
   OFF в интерфейсе не является доказательством электрического OFF.
5. Сборочный CI-образ без private config/CA имеет отключённую сеть:
   отсутствие MQTT у такого образа ожидаемо, не повод отключать TLS.

## Этап B: изолированная сеть, по-прежнему без реле

Требуются отдельно согласованные lab identity, CA, ACL, Wi-Fi и Core/MQTT.
Не использовать production БД, секреты или identity программного эмулятора.
Не менять `qualified=false`, физические guards или production-права.

| Проверка | Ожидаемый результат |
|---|---|
| Неверные CA/hostname/credentials | Соединение отклонено, insecure fallback отсутствует |
| Корректная сеть | TLS, необходимые SUBACK, status/heartbeat; не разрешение GPIO |
| Обычная физическая команда через Core | HTTP 409 до публикации/создания команды; успешный ACK не ожидается |
| Отдельно reviewed lab candidate/permit | Настоящий worker остаётся fail-closed: rejected ACK, ноль command-driven GPIO writes |
| Повтор/retained/старый permit | Повторного исполнения нет; исходный deadline не продлевается |
| Wi-Fi/broker reconnect | Новая session; старый grant не исполняется; статус восстанавливается |
| Reboot платы | Новый boot ID, GPIO OFF; старый permit не исполняется |
| Restart Core | Новая epoch/recovery fence; старые grants автоматически не перевыдаёт |

Невозможность увидеть grant через штатный физический API ожидаема при закрытом
допуске. Не обходить guards для выполнения этой таблицы; lab permit-тест требует
отдельного утверждённого harness. Потеря связи сама по себе не является командой OFF.

## Программная контрольная проверка ACK/state

На отдельном программном реле той же Core-версии выполнить ON/OFF:
одна команда, корректно связанные ACK **и** state. Чужая correlation, противоположный
state и один ACK без подтверждённого состояния не должны означать успех.
Повтор того же запроса не создаёт вторую команду. При неизвестном исходе/сбое
не делать слепой повтор. Это software acceptance, не результат реальной платы.

## Граница первого испытания

**Не подключать сетевое напряжение, нагреватели, насосы, ворота, газовое/пожарное
оборудование или любые опасные нагрузки. Не подавать питание на них из этого стенда.**
Контакты реле в этапах A/B не подключаются вообще. Даже низковольтный тест контактов
требует отдельного рассмотрения схемы и разрешения после A/B и необходимых
timing/NVS испытаний. Нельзя переносить host timing bounds на реальную плату.

Итоговый протокол наставника: что реально проверено отдельно для WROOM и C6,
версии, условия, измерения, ожидаемое/фактическое, ошибки и «не проверено».
Приёмку не отмечать завершённой по одной успешной загрузке или зелёному CI.
